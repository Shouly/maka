## 2. Runtime Host connection
- The renderer **never** uses `@maka/runtime-host/client` at runtime; all `@maka/runtime-host/*` imports are `import type` except constants `MESSAGE_QUEUE_MAX_ENTRIES`, `runtimeHostProfileUsesHostWorkspace`, `isCanonicalRuntimeHostWebSocketPath`, `PROJECT_DIRECTORY_MAX_ROOTS`. The preload owns multi-host scopes and rewrites ids.
- `subscribeEvents` (preload.ts:2256–2317): mints observerId, resolves host ref, subscribes `sessions:event:<hostSessionId>` + `sessions:observation-seed`, `invoke('sessions:observe')` -> `onSeeded()`/`onSeedError()`, teardown `sessions:unobserve`; every event projected through `projectDesktopSessionEvent`.
- Renderer reference: `renderer/app-shell-effects.ts:318–500` `useActiveSessionEvents`: one layout effect keyed on `[activeId, observationAuthorityRevision]` creating `DesktopTranscriptRangeStore(activeId)` (`renderer/desktop-transcript-range-store.ts`), `window.maka.transcripts.open(...)` wrapped in `createRecoveringDesktopTranscriptRangeController`, `sessions.subscribeEvents` with exponential backoff on seed error (100ms x 2^n, cap 2s), health via `recordSessionEventStreamEvent`, then `handleEvent`.
- `SessionEvent` union (`packages/core/src/events.ts:552–582`): `text_delta, text_complete, thinking_delta, thinking_complete, tool_start, tool_output_delta, tool_progress, tool_result_preview, tool_result, permission_request | additional_permission_request | sandbox_escalation_request, sandbox_boundary_request, sandbox_boundary_decision_ack, client_capability_request, client_capability_decision_ack, permission_answer_ack, permission_closure_ack, permission_decision_ack, user_question_request, user_question_answer_ack, form_request, form_answer_ack, plan_submitted, token_usage, steering_message, message_admission, queue_update, provider_retry, error, complete, abort`. `ActiveInteractionRequestEvent` = `sandbox_boundary_request | user_question_request | form_request | client_capability_request`.

### Data flow (reference implementation)
```
sessions.subscribeEvents -> createAppShellSessionEventHandlers().handleEvent   [app-shell-session-events.ts:294-460]
  display deltas for the ACTIVE session batched to next rAF (fallback 100ms) -> replaceLiveTurns
  other events flush batch then: applyLiveTurnEvent(projection, event, locale)  [@maka/ui live-turn-projection.ts]
                                 reduceInteractionQueues(queues, sessionId, event) [@maka/ui interaction-queue.ts]
  side effects: queue_update -> projectQueuedTransientMessages; message_admission 'retracted' -> removeTransientMessage;
    steering_message -> drop tail row; text_complete -> refreshMessages({requiredAssistantMessageId}); tool_result -> refreshMessages;
    *_request / *_ack -> onInteractionChanged; sandbox_boundary_decision_ack -> onExecutionBoundaryChanged;
    error -> toast (model-connection-errors.ts), notifyRunEnded('errored'), refresh; abort -> clearInteractions, refresh;
    complete -> clearInteractions, contextCompactionOutcome, notifyRunEnded('completed'), refresh, handoffAssistantStreaming (3x120ms)
state: liveTurnBySession, interactionBySession, messageQueueBySession, messages (from transcripts.open batches via DesktopTranscriptRangeStore.accept().snapshot())
  -> useTranscriptProjection({sessionId, locale, messages, liveTurn, shellRunUpdates})  [@maka/ui]

turn actions: regenerate -> sessions.regenerateTurn; branch -> acquireSessionCopyAttempt + sessions.branchFromTurn; stop -> sessions.stop;
  compact -> sessions.compact; revise -> reviseBeforeTurn; resume -> sessions.resumeLatest. Shell reads a low-entropy LiveTurnSnapshot, not the projection.
```
